# P5-S7-T02｜清洁构建、烧录与复现演练

> 教程状态：`FROZEN`（内容审核通过：2026-08-15）
> 执行路径：`CLEAN_SOFTWARE_REPRODUCTION_FIRST`
> 软件结果：`PASS_CLEAN_REPRODUCTION`
> 硬件结果：`WAITING_FOR_HARDWARE / NOT_RUN`
> 基线：`[036] 15932a2ff7adecdfbe5355559926a95b0df25845`

## 1. 为什么不能直接复用当前 out

已有工作区构建通过，只能说明当前目录在已有缓存和产物条件下可以继续工作。清洁复现需要从
已提交文件重新开始，排除未跟踪文件、旧 CMake cache、对象文件和本机临时修改的影响。

本轮先确认 Windows 与 Ubuntu 同为 `[036]`，并以 Ubuntu 权威仓库的本地 `git archive` 建立
只含已跟踪文件的临时源目录。整个过程不联网，也不使用仓库原有 `out/`。

## 2. replay runner 做了什么

新增的 `tools/reproduce_release_candidate.py` 只使用 Python 标准库，主要负责：

1. 拒绝错误 HEAD 或 dirty 源仓库；
2. 导出并安全解包本地 Git archive；
3. 在空目录运行 Host、合同、ARM 和资源检查；
4. 对命令设置超时和日志上限；
5. 记录工具版本、提交、资源值和少量关键 SHA-256；
6. 清理经过路径边界确认的专用临时目录。

runner 自测覆盖路径穿越、日志截断、SHA-256 稳定和 manifest 排序等 10 个有界检查。它不执行
`git add`、commit、push、tag 或任何远端操作。

## 3. 实际清洁复现结果

clean `[036]` 中实际通过：

- Host Debug 与 Release 各 21/21；
- release-readiness 正常检查及 10 项自测；
- Modbus、CAN、BSP 合同与负向自测；
- ARM Debug/Release configure、build 和 ELF/HEX/BIN/MAP 生成；
- 静态资源、零 heap reserve 和禁止动态分配门。

清洁构建资源为：

| 配置 | text | data | bss | Flash | linked RAM |
|---|---:|---:|---:|---:|---:|
| Debug | 53224 B | 160 B | 13224 B | 53384 B | 13384 B |
| Release | 44360 B | 156 B | 13216 B | 44516 B | 13372 B |

因此可以关闭软件二进制候选的 `REPRO-001`，但这不代表已经烧录或实机运行。

## 4. 为什么第二次 Release 哈希不同

本轮额外在第二个独立目录重复了 Release 构建。两次编译和链接都通过，但 BIN/HEX 不同。

排查发现固件中保留了 FreeRTOS `tasks.c`、`queue.c` 和 `port.c` 的绝对 `__FILE__` 路径。两个
临时目录名称长度不同，使 Release text 从 44360 B 变为 44380 B，并改变后续地址和文件哈希。

因此本轮结论是：

```text
从零完成相同构建流程 = PASS
跨不同目录字节完全相同 = NOT_CLAIMED / PATH_DEPENDENT
```

没有为了追求漂亮结论而修改 CMake、FreeRTOS 断言或固件选项。未来若需要确定性二进制，可单独
评审 `-ffile-prefix-map` 等方案，并重新验证崩溃定位信息和资源变化。

## 5. 实际遇到的另一个问题

`tools/capture_tool_versions.sh` 带 CRLF，Ubuntu 直接执行时报：

```text
/usr/bin/env: 'sh\r': No such file or directory
```

本轮 runner 改为直接调用各工具的 `--version`，不依赖该 wrapper。由于批准的九文件允许清单不
包含这个旧脚本，本轮只记录问题，不越界修改；它不影响 runner、Host 或 ARM clean replay。

## 6. 为什么没有执行烧录

用户没有提供新的板卡到货和接线入场事实，Ubuntu 中也没有现成的 USB 枚举命令或烧录器。因此
本轮没有安装工具、透传 USB、调用 ST-LINK，也没有打开串口、RS485 或 CAN。

硬件状态保持：

```text
flash / verify / reset = NOT_RUN
sensors / Modbus / CAN = NOT_RUN
hardware Release       = BLOCKED_WAITING_FOR_HARDWARE
```

这不会否定已经完成的软件清洁复现，也不能被改写为硬件 PASS。

## 7. 保留了哪些证据

公开仓库只保留：

- `artifacts/release/p5_s7_t02_replay.json`；
- `artifacts/release/p5_s7_t02_candidate_manifest.sha256`；
- `docs/reproduction_report.md`；
- 本教程及必要的 README/ledger 状态更新。

不提交 source tar、固件二进制、对象文件、整个 `out/` 或完整构建日志。出现问题时，优先使用提交、
失败命令、资源值和目标 SHA-256 定位，而不是长期积累不会被消费的大型证据包。
