## 1. 本工作块解决什么问题

项目现已完成软件、交叉构建、虚拟总线以及有界实物硬件证据，不等于已经获得最终发布授权。T05
把当前可交付内容整理成候选说明、演示入口和求职声明，同时保留计量、生产部署、重复故障、MTBF

本轮不会因为任务名包含 v0.1.0 就创建 tag 或远端 Release，也不会把候选句自动写入简历。

## 2. 四个容易混淆的概念

```text
intended version = 未来希望发布的版本号
bounded hardware candidate = 软件与有界硬件证据完成、等待 exact commit 发布复核
release candidate = exact commit 已通过全部发布前门
published release = 用户授权后已 tag 并创建远端 Release
```

本项目当前到第三层之前：有界硬件证据已完成，但 exact release commit、tag 和远端 Release 尚未
选择或授权。

## 3. 为什么保留两个提交身份

`[036]` 是 T02 clean replay 的真实输入，包含无缓存、无网络的 Host/ARM/资源复现和固件哈希。
`[039]` 是当前教程和候选材料基线。两者之间产品、构建和测试输入没有变化，但不能据此把 `[039]`

## 4. 如何从证据矩阵生成声明

正面声明只消费 `PASS` 行，并保留执行层限定：

- `HOST` 表示主机逻辑或合同；
- `CROSS_BUILD` 表示 ARM 编译、链接和镜像生成；
- `VIRTUAL_BUS` 表示 SocketCAN/vcan；
- `SOFTWARE_CANDIDATE` 表示实现和软件验证边界；
- `BOUNDED_HARDWARE_INTEGRATION` 与 `BOUNDED_HARDWARE_SOAK` 表示只在所引证的实物、时长和
  排除项内成立。

`NOT_RUN` 只能写入限制，不能改成“基本完成”“待优化”或“已联调”。`NOT_CLAIMED` 表示主动不做该
结论，例如不同 clean 路径的 bit-for-bit 固件一致性。

## 5. 三类岗位为什么使用不同表达

事实不变，只改变关注点：

- 嵌入式岗位强调 STM32/FreeRTOS、Host 回归、ARM 构建、资源门和 BSP/中断边界；
- IoT 岗位强调 Modbus/CAN 软件合同、SocketCAN/vcan 和软件故障隔离；
- 机器人底层岗位强调固定资源、消息路径、背压、恢复和数据所有权。

候选句集中在 [`../recruitment_claim_ledger.md`](../recruitment_claim_ledger.md)。物理传感器、项目三、
物理 CAN 和硬件长稳只能在当前 PASS 行及其限定边界内使用，不得扩大为计量精度、生产 MQTT、
任意故障恢复或生产级可靠性。
