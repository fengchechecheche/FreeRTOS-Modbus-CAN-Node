```text

published release = 用户授权后已 tag 并创建远端 Release
```

## 4. 如何从证据矩阵生成声明

正面声明只消费 `PASS` 行，并保留执行层限定：

- `HOST` 表示主机逻辑或合同；
- `CROSS_BUILD` 表示 ARM 编译、链接和镜像生成；
- `VIRTUAL_BUS` 表示 SocketCAN/vcan；
- `SOFTWARE_CANDIDATE` 表示实现和软件验证边界。

`NOT_RUN` 只能写入限制，不能改成“基本完成”“待优化”或“已联调”。`NOT_CLAIMED` 表示主动不做该
结论，例如不同 clean 路径的 bit-for-bit 固件一致性。

## 5. 三类岗位为什么使用不同表达

事实不变，只改变关注点：

- 嵌入式岗位强调 STM32/FreeRTOS、Host 回归、ARM 构建、资源门和 BSP/中断边界；
- IoT 岗位强调 Modbus/CAN 软件合同、SocketCAN/vcan 和软件故障隔离；
- 机器人底层岗位强调固定资源、消息路径、背压、恢复和数据所有权。

候选句集中在 [`../recruitment_claim_ledger.md`](../recruitment_claim_ledger.md)。物理传感器、项目三、
物理 CAN 和硬件长稳没有因为换了岗位方向而变成可声明能力。
