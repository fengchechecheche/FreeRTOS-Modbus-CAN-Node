# P5-S5-T03 RS485 接收状态机与半双工时序

## 目标与边界

本任务把 T02 的“完整缓冲区 ADU 解码”接到 USART1/RS485 候选运行路径：用固定内存拼接 64 B Normal-DMA chunk，按 t1.5/t3.5 管理 RTU 帧，并把 TX 方向切换顺序做成可测试状态机。功能码处理、寄存器写入和真实应答留给 T04；无硬件阶段不把编译与 Host 测试写成实物验收。

## 为什么分成 ISR、任务和纯状态机

- ISR 只记录 `kind + length + DWT timestamp` 并通知 `protocol_task`，避免在中断中复制、CRC、重装 DMA 或等待。
- BSP 任务路径复制 1～64 B chunk 并立即重新 arm RX。
- `p5_modbus_rtu_stream` 不依赖 HAL/FreeRTOS，Host 可覆盖边界条件。
- 唯一 256 B stream buffer 由 `protocol_task` 使用；不新建 task、queue、mutex 或 heap。

## 接收状态机

`IDLE` 收到首字节进入 `RECEIVING`。相邻字节的静默时间为“本字节结束时间减上字节结束时间，再减一个字符时间”：

- `silence <= t1.5`：继续接收，精确等于 t1.5 仍有效；
- `t1.5 < silence < t3.5`：整帧无效，进入 `DISCARD_UNTIL_GAP`；
- `silence >= t3.5`：结算上一帧，并以当前字节开始新帧；
- 第 257 字节：只记一次 overlong，丢弃直到 t3.5；
- 无新字节时由 `poll()` 在 t3.5 到期后结算。

所有时间差均用 `uint32_t` 无符号减法，因此 DWT 回绕不破坏短间隔判断。计数器饱和，不保存原始错误帧历史。

## Normal-DMA 的限制

IDLE 回调捕获点比最后字节结束约晚一个字符；DMA TC 捕获点近似最后字节结束。任务按固定 tchar 反推同一 chunk 内各字节时间。这个方法不能证明物理总线上 1.0～1.5 字符的内部停顿已被准确识别，因此当前结论只到软件候选。

## 半双工发送

发送前先复制最多 256 B caller 数据，再停止 RX DMA、拉高 DE、启动 TX DMA。最终 USART TC 回调立即拉低 DE；任务随后记账并重装 RX。任一步失败都回到接收或故障恢复，不让同一 UART 同时处于 RX DMA 和 TX DMA。

## 验证结果

- Host Debug/Release：16/16；新增 stream 用例覆盖有效帧、短帧、CRC、t1.5、t3.5、超长和回绕。
- ARM Debug/Release：构建通过。
- linked static RAM：Debug 11,808 B，Release 11,804 B；相对 A0 分别增加 464 B、472 B。
- 实板 DE、DMA/IDLE 时间戳误差、真实 RS485 收发：`WAITING_FOR_HARDWARE / NOT_RUN`。

## 实际问题与修复

基线资源脚本需要同时传入 Debug/Release 的 ELF 与 map，计划中的简写参数不能运行；实施时改用脚本当前真实接口。核心代码首轮即通过 Host 与 ARM 构建，没有产生需要保留的大量诊断数据。
