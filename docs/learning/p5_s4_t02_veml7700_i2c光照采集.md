# P5-S4-T02 VEML7700 I²C 光照采集

## 目标与边界

本任务把 S2 的 VEML7700 address/register presence 探针推进为可测试的持续采集
驱动：配置 ALS、等待积分、读取 raw、换算整数 millilux，并用有限自动量程兼顾暗光
和强光。开发板和传感器尚未到货，因此 PASS 只代表 Host、ARM 构建和静态合同通过。

## 关键设计与实施

VEML7700 的 7-bit address 固定为 `0x10`。寄存器是 16-bit word，但 I²C 数据顺序
是 low byte first；例如默认 config `0x1000` 写到总线是 `00 10`。将 address 左移
只发生在 HAL BSP 边界，pure driver 和应用层始终保存 `0x10`，可避免重复左移。

驱动分成三层：`sensors/veml7700` 保存寄存器、整数换算和状态机；
`app_veml7700` 注入 BSP read/write；`acquisition_task` 仍是 I²C2 唯一运行时 owner。
配置 read/write/verify、积分等待和 ALS read 每次只推进一步，所以一个 20 ms release
最多执行一笔 I²C transaction。

照度分辨率由 gain 和 integration time 决定。固件把每 count 的分辨率保存为
`0.0001 lx` 整数，再用 64-bit 中间量换算 millilux，避免把浮点运行库带入固件。
9 级表覆盖 x1/8、25 ms 到 x2、800 ms。raw `<=100` 向更灵敏一级移动，
raw `>=10000` 向更不灵敏一级移动；每次只移动一级，最多 8 次，量程变化后重新等待
积分，不发布旧量程下的 raw。

高于约 1000 lx 的样本只增加 `HIGH_LUX_UNCORRECTED` 标记。官方应用说明中的高照度
修正与封装窗口、光学结构和应用条件相关，本阶段保留基础换算，避免把未实测的模型
包装成精度结论。

NACK、BUSY、timeout、I/O error 和 config mismatch 分开记录。瞬态错误最多请求一次
recovery；当前 adapter 明确返回 unavailable，因为无硬件条件下无法证明 SCL pulse、
SDA release 或 I²C peripheral re-init 有效。错误不会停止其他任务，也不会直接改变
watchdog feed decision。

## 验证结果

- Host Debug/Release：均为 11/11；
- word/config、5 个整数换算向量、阈值、两端量程、tick wrap 和错误恢复：PASS；
- 每次 VEML service 最多一笔 transaction：PASS；
- ARM Debug/Release 构建链接：PASS；
- Flash：34844 B / 29564 B；Static RAM：9792 B / 9784 B；
- 无 VEML 照度相关 `__aeabi_d*`/`__aeabi_f*` helper；
- VEML7700 实物身份、采集、自动量程和精度：`NOT_RUN`/`NOT_CLAIMED`。

## 实际问题与修复

Release 主机测试会定义 `NDEBUG`，导致标准 `assert` 被编译掉并触发测试变量未使用。
测试入口在包含 `assert.h` 前撤销 `NDEBUG`，从而保留 Release 优化的同时确保断言真正
执行。契约检查器原先还只允许旧的 BME 调用字面量；接入共享 `now_ms` 后同步收紧为
“同一 acquisition release 依次调用 BME/VEML”，并加入第二 I²C owner 等负向变异。
