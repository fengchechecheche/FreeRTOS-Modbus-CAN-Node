# P5-S4-T05 多传感器调度与故障注入

## 目标与边界

本任务不再增加传感器，而是验证 BME280、VEML7700、ADXL345 在同一 acquisition owner
下的组合行为。故障仅由 Host fake transport 注入；生产固件没有测试后门。无硬件结论只到
`READY_FOR_CONTENT_REVIEW + READY_FOR_HARDWARE`。

## 关键设计与实施

保留 20 ms 固定周期顺序：ADXL 周期推进、BME、VEML、统一 measurement、sensor
monitor。IRQ 通知聚合后最多读一帧 ADXL，不能按通知数循环补读。

新增的 pure `app_sensor_monitor` 不访问 HAL/RTOS，也不控制恢复。它只保存四 source 的
accepted count 和 last/min/max interval、三设备的 fault episode 与 recovery 摘要、当前
unavailable/stale/recovery mask，以及 ADXL IRQ/drop 摘要。所有结构固定大小，不保存 raw
history。

health 接收三个 mask。局部传感器故障只产生 warning 和 `DEGRADED`，feed 保持
`ALLOWED`；既有 task stall、全局恢复耗尽和 reset-loop 合同才允许升级复位。

## 验证结果

- Host Debug/Release：14/14 PASS；
- 联合矩阵覆盖 healthy、BME timeout/identity、VEML missing/config、ADXL repeated
  IRQ/timeout、tick wrap、局部降级和 queue bound；
- 静态合同：489 项 PASS，自检拒绝生产注入、monitor 无界循环和 sensor-reset 扩散；
- Firmware Debug/Release：`40648/160/11184` 与 `34064/156/11176` B；
- 相对 `[023]` RAM：Debug +552 B、Release +544 B；静态内存合同 PASS。

这些是虚拟时间和交叉构建结果，不是实物 WCET、jitter、恢复或 60 分钟运行证据。

## 实际问题与修复

联合测试暴露：VEML7700/ADXL345 进入终态 `OFFLINE` 后，仅按当前状态分类会丢失导致
离线的原始原因。修复方式是在 monitor 分类时同时读取既有 `last_error_status`，使
not-present、timeout、I/O 和 configuration 根因在终态仍可排查；没有修改驱动或扩大
恢复策略。

此外，静态合同脚本初版新增分支缺少一个右括号，Python 语法检查立即阻断执行；修正后
正常检查和全部负向自检通过。
