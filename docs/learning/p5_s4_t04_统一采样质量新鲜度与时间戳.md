# P5-S4-T04 统一采样、质量、新鲜度与时间戳

## 目标与边界

三个传感器驱动已经能产生整数工程量，但它们的状态、质量和更新频率不同。本任务
增加 app 层统一投影，让未来 Modbus、CAN 和 health task 读取同一份 latest-value
合同。它不修改 pure driver，不实现协议，也不保存样本历史。

开发板仍未到货，因此软件通过只代表 Host、ARM 构建和静态合同闭合。真实采样时刻、
jitter、总线组合 WCET 和断线状态仍为 `NOT_RUN`。

## 为什么是四个 source

BME280 和 VEML7700 约每秒更新一次，ADXL345 即时 XYZ 约 100 Hz，而振动特征要
等 100 个有效样本才形成。如果 ADXL sample 和 feature 共用 timestamp，快速 XYZ
会不断把旧 RMS/peak 标记为新数据。因此 schema 把它们拆成四个独立 source，分别
保存 sequence、sample time、age 和 freshness。

## 时间与 sequence

`sample_monotonic_ms` 不是物理采样瞬间，而是 acquisition task 第一次接纳新有效
sequence 的 1 kHz tick。相同 sequence 不刷新时间；sequence 从 `UINT32_MAX` 回到
0 仍被视为变化。age 使用无符号减法，因此 tick wrap 后仍能得到短时间差。

freshness 使用宽松上限：BME 2500 ms、VEML 3000 ms、ADXL sample 200 ms、ADXL
feature 2500 ms。边界本身仍 fresh，下一毫秒才 stale。正常 forced conversion、
integration/ranging 或等待 IRQ 不会因为 transient driver status 立即失效。

## invalid、stale 和 offline

没有 last-good 时为 invalid，checked field accessor 返回 unavailable 且不修改输出
参数。这样零初始化内存不会冒充真实的零工程量。超过 age 上限后为 stale；driver
进入 terminal state 后为 offline。两者若有 last-good 都保留值，同时设置
`value_is_retained=true`，sequence 和 sample time 不变。

公共 quality 只保留未校准、量程警告、饱和、gap、drop、transport/config error 和
recovery 八类。raw、range level 和详细计数仍留在 owner-local snapshot，避免公共
schema 膨胀成第二套驱动状态机。

## 所有权与并发

`acquisition_task` 仍是 SPI1/I²C2 唯一 runtime owner。它在总线操作结束后更新纯
逻辑 model，再用既有 zero-wait snapshot mutex 复制完整对象。消费者只在 mutex 内
复制，解锁后才计算 age 或读取字段。没有新增 task、queue、mutex、heap 或 bus lock。

owner input 使用固定静态对象，避免在 256-word acquisition stack 上同时放置三个
driver snapshot 和统一候选副本。实际 stack watermark 仍需硬件运行后测量。

## 逻辑字段不是协议地址

17 个 field ID 固定字段、source 和单位：centi-°C、Pa、milli-%RH、millilux 和
millig。ID 只用于内部 schema。S5/S6 必须显式选择寄存器数量、报文、endianness 和
saturation policy，不能把 C struct 的 padding 或 enum layout 直接放到 wire。

## 验证结果

- Host Debug/Release：13/13 PASS；
- BSP contract：422 stable facts PASS，负向自检通过；
- Firmware Debug/Release：build/link PASS；
- Debug Flash/RAM：39464/10792 B；
- Release Flash/RAM：33148/10788 B；
- 相对 `[022]` RAM 均增加 600 B，低于 1 KiB 异常审查阈值；
- 五个 task stack、queue depth 8、linker heap 0 不变。

## 实际问题与处理

1. Windows 对 Ubuntu UNC 文件再次出现 access denied。实现没有绕过补丁审查，而是
   在规划仓库精确中转目录中编辑允许文件，再由 Ubuntu 内部机械复制回权威仓库。
2. 如果直接用 driver transient status 判 freshness，BME 正常 conversion wait 和
   VEML ranging 会频繁抖成 stale。最终以 last-good age 判 fresh/stale，只把当前
   error/recovery 放入 quality，terminal state 才直接 offline。
3. ADXL sample 和 feature 最初看似可以共用一个 source，但 Host 设计审查发现 100 Hz
   sample 会错误刷新 1 Hz feature。最终拆为独立 sequence/time，并加入回归向量。
4. 统一 model、共享 snapshot 和三个 owner input 会增加静态 RAM。输入对象保持静态以
   保护 acquisition stack；链接实测增量为 600 B，没有保存 raw history。
