# P5-S3-T02｜静态内存、栈与资源预算

## 目标与边界

本任务为 STM32F446RE 固件建立可追踪的静态资源上限，并为后续板上栈高水位检查准备接口。无硬件阶段
可以验证对象是否静态创建、ELF/MAP 是否符合 RAM/Flash 上限，但不能填写真实任务栈余量。

## 关键设计与实施

五个应用任务分别持有 256 words 静态栈，不再共用一个“临时栈大小”常量。这样后续 protocol、
acquisition、CAN、health 和 diagnostic 任务可以独立调整，而不会误改其他任务。

FreeRTOS 继续关闭动态分配，不加入 `heap_x.c`。CubeMX 链接脚本原有 512 B 默认 heap 被改为 0，
MSP/异常栈仍保留 1024 B。五个应用任务栈共 5120 B；加上 idle task 和 MSP，显式栈预留共
6656 B。

`uxTaskGetStackHighWaterMark()` 已开启。`health_task` 每秒把五个任务的结果更新到内存快照，不持续
打印或写文件。资源快照返回配置深度、历史最小剩余 words 和 `measured` 标志；scheduler 尚未运行时
明确返回“未测量”，避免把 0 写成真实结果。

资源工具读取 Debug/Release ELF 与 MAP，并检查：

- linker heap 为 0、MSP 预留为 1024 B；
- 项目自有代码和最终 ELF 没有意外 allocator；
- Flash 不超过 384 KiB；
- 已链接 RAM 不超过 96 KiB。

上限均为 128 KiB RAM、512 KiB Flash 的宽松 75% 门，目的是提前发现无界增长，不阻塞正常功能开发。

## 验证结果

Host Debug/Release 各 6/6 通过。Firmware Debug/Release 均完成交叉编译和链接。

| 配置 | Flash | 已链接 RAM |
|---|---:|---:|
| Debug | 18848 B（3.59%） | 8776 B（6.70%） |
| Release | 16528 B（3.15%） | 8768 B（6.69%） |

资源工具返回 `PASS: static-only linker and resource budget contract`。MAP/ELF 属于 ignored 构建产物，
正常通过时不复制为长期证据。

## 实际问题与修复

首次统计将 MSP 预留再次加到 `data + bss`，检查后发现 GNU `size` 已把 NOLOAD
`._user_heap_stack` 计入 `bss`。工具改用 `data + bss` 作为已链接 RAM，MSP 仍在明细表单列，避免
重复计算。

## 限制与下一步

板卡尚未到货，五个任务 watermark 均为 `NOT_MEASURED`。到货后只需运行约 10 秒 scheduler smoke，
读取一次资源快照；少于 32 free words 的任务增加 64 words 后重测。空骨架余量不能用于缩栈，S4～S6
接入传感器、Modbus、CAN 和恢复场景后仍要复测相关任务。
