# P5-S4-T03 ADXL345 中断采样与振动特征

## 目标与边界

本任务建立最小可测试链：

```text
ADXL345 DATA_READY -> PB4/EXTI4 -> counting notification
-> acquisition_task -> six-byte SPI read -> integer feature window
```

软件只证明配置、解析、调度和特征算法一致；硬件 identity、时序、轴方向和振动
响应保持 `NOT_RUN`。不在本任务实现 FIFO、FFT 或故障模型。

## coherent SPI 与二补码

ADXL345 SPI 命令的 D7 是 read，D6 是 multibyte。由 `DATAX0=0x32`
连续读取六字节时：

```text
0x32 | 0x80 | 0x40 = 0xF2
```

这个 D6 只对 ADXL345 长度大于 1 的读取启用，不能机械套用到 BME280。
XYZ 每轴 low byte first，必须先组合为 `uint16_t`，再明确转换为 signed
`int16_t`，避免依赖主机字节序或未定义的移位行为。

## 中断与绝对释放

EXTI4 priority 为 6/0；FreeRTOS 最大 syscall priority 为 5，因此 ISR 可以调用
`vTaskNotifyGiveFromISR()`。callback 不读 SPI，只做 pin admission、计数和通知。

task notification 是事件计数，不是原始样本队列。一次唤醒即使累计 3 个事件，也只
读取最新一帧，并记录至少丢失 2 帧。事件服务结束后立即检查原有 20 ms release，
所以 DATA_READY storm 不会无限推迟 BME280/VEML7700。

## 去直流 RMS、peak 与整数实现

窗口保存 100 个样本的累计量，不保存 100 帧数组。使用
`N*sum_square-sum*sum` 得到去直流方差分子，再用整数根计算 RMS。peak 由
min/max 相对窗口 mean 得到。常量 `[0,0,1000]` 的去直流 RMS 为 0；
交替 ±1000 的 RMS/peak 均为 1000；50% step 的 mean/RMS/peak 均为 500。

这类特征能展示趋势，但没有频率信息，不能直接推导轴承故障、共振或设备健康等级。

## 错误与恢复

driver 区分 wrong ID、BUSY、timeout、I/O、config mismatch 和 DATA_READY stall。
一次故障 episode 最多重配一次；重复失败进入 offline。read error 与合并事件都会
在下一有效样本和窗口中保留 gap/drop 质量，不把断点伪装成连续采样。

## 验证结果

- Host Debug/Release：各 12/12；
- Firmware Debug/Release：构建和链接通过；
- 静态合同：382 项通过；
- priority 0、缺失 ADXL multibyte、无界 loop、扩大 recovery 和 callback
  `memcpy` 负向 mutant 均被拒绝；
- 五个任务、每任务 256-word stack、queue depth 和 linker heap 均未改变；
- 实物路径仍为 `LINKED_NOT_EXECUTED + WAITING_FOR_HARDWARE`。

## 实际问题与修复

1. CubeMX 生成 EXTI4 时附带了超范围 CMSIS/CMake/syscalls 和链接脚本改写。
   先备份，再只保留四个允许文件，并恢复 heap、priority group 和 FreeRTOS handler
   ownership。
2. 静态检查最初把纯整数函数名 `integer_sqrt` 误认为浮点 `sqrt` 调用。
   将函数改名为 `integer_root` 后，规则可以继续直接拒绝真正的
   `sqrt/sqrtf`，且不降低检查强度。
3. Windows 到 WSL 的 UNC 共享允许新建但拒绝后续补丁更新。实施时在规划仓库建立
   临时补丁区，全部语义修改通过补丁完成，再按明确 allowlist 复制到 Ubuntu；Windows
   实现镜像保持 clean。
